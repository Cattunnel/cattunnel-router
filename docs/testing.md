# Тесты

В каталоге `tests/` лежат два набора проверок: быстрые модульные тесты и стенд с контейнерами для проверки установки, обновления и правил сети.

## Модульные тесты

```
python3 -m unittest discover -s tests -v
```

Тесты запускают настоящие скрипты роутера (`common/cattunnel`, `common/upgrade.sh`, `install.sh.in`) и curl, а границы системы заменяют заглушками. Docker и root не нужны. Если в `PATH` есть настоящие `age` и `age-keygen` (или задан `CATTUNNEL_TEST_AGE_DIR`), часть тестов использует их, иначе подставляются заглушки.

| Файл | Что проверяет |
|---|---|
| `test_device_key.py` | ключ устройства и обмен одноразовой ссылки, зеркала подписки, расшифровка новым и запасным ключом, выбор способа анти-DPI, проверка сети роутера, сборка конфига движка |
| `test_report.py` | `cattunnel report` полезен и не выдаёт подписку, пароли и ключи |
| `test_upgrade.py` | временная блокировка при обновлении, откат файлов и базы пакетов, блокировки установщика, разница между обычной остановкой и `stop --force` |
| `test_matrix_safety.py` | защитные проверки самого стенда |

## Стенд с контейнерами

Стенд проверяет пакеты в изолированных контейнерах OpenWrt 24, OpenWrt 25 и Entware, без выхода в интернет. Вместо настоящего движка работает маленький тестовый движок с реальными TUN и SOCKS5. Поэтому стенд подтверждает правила сети и жизненный цикл службы, но не совместимость с сервером TrustTunnel и не скорость на настоящем роутере.

```text
контейнеры OpenWrt 24, OpenWrt 25, Entware
   |                      |
 клиент в LAN ---> роутер (пакет CatTunnel) ---> внешний узел и узел выхода
   |
 счётчики правил, захват пакетов на WAN, ответ HTTP напрямую
```

Рисунок 1. Схема стенда: клиент, роутер и два внешних узла в изолированных сетях.

Контейнеры создаёт `tests/create_router_containers.sh` из локальных образов (`LAB_DIR`, `OW24_IMAGE`, `OW25_IMAGE`, `ENTWARE_IMAGE`, `ENDPOINT_IMAGE`). Перед запуском проверяется, что контейнеры не привилегированные и в них нет `/dev/watchdog`. Дальше работают:

- `router_matrix.py` (нужен root): перебирает платформы, режимы `tun` и `socks`, пустой и непустой `DEVICES` и десять операций: обновление, переустановка, перезапуск, остановка, удаление, откат, `stop --force`, удаление во время обновления, переустановка остановленной службы и переустановка с выключенным автозапуском. Ключ `--ipv6` проверяет IPv6, `--dns-cleanup` возврат DNS, `--exchange-import` импорт одноразовой ссылки.
- `router_recovery.py`: зависшие блокировки и метки обновления, убитый процесс установщика и перезапуск контейнера.
- `router_tls.py <arch>`: снимает ClientHello настоящего движка под qemu-user на локальный адрес. Это проверяет отправляемый пакет, а не успешное соединение.

## Не проверено

- ASUS Merlin: пакет и команды те же, что для Entware на Keenetic, но стенда для Merlin нет.
- Настоящие роутеры: стенд работает на x86_64 в контейнерах, бинарники других архитектур запускаются только под qemu-user.
- Переключение nikki на запасной VLESS при отказе CatTunnel.
- Сообщения установщика «SHA-256 не совпал» и «зеркало не отвечает» разобраны по коду, а не воспроизведены.
