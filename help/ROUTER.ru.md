# CatTunnel на роутере

CatTunnel на роутере использует TrustTunnel с патчами CatTunnel и получает серверы из той же подписки, что приложение. На OpenWrt управление доступно в LuCI через «Службы → CatTunnel», на Keenetic и ASUS Merlin - через Entware и отдельную веб-страницу.

## Быстрый старт

1. Установить пакет по SSH: `curl -fsSLO https://github.com/Cattunnel/cattunnel-router/releases/latest/download/install.sh && sh install.sh`. Установщик выбирает систему и архитектуру, проверяет ресурсы и SHA-256 пакета; при несовместимости объясняет причину отказа.
2. Добавить одноразовую ссылку от сервера подписок в «Настройки → Подписка» или выполнить `cattunnel import '<ссылка>'`. Ссылки `/api/go/<код>` и `cattunnel://subscription?code=...&base=...` обмениваются на постоянный адрес подписки с привязкой к открытому ключу роутера; одноразовый код не сохраняется. Постоянная ссылка также поддерживается, прежний ключ пользователя можно пропустить нажатием Enter либо передать вторым аргументом: `cattunnel import '<ссылка>' '<ключ>'`.
3. Выбрать сервер на вкладке «Серверы» и нажать «Запустить» на вкладке «Состояние». Проверка доступности находится на той же странице и вызывается командой `cattunnel test`.

Отдельная страница включается командами `cattunnel web password <пароль>` и `cattunnel web on`; пароль должен содержать не менее 8 символов. Страница открывается по адресу `http://<адрес роутера>:8090` с именем пользователя `admin`; эти команды доступны и на OpenWrt.

## Режимы

Режим `socks` включён по умолчанию: CatTunnel предоставляет SOCKS5 для mihomo, nikki или другого прокси. Маршрутизацию в этой схеме задаёт внешний прокси, поэтому российские исключения CatTunnel и обычные правила `DEVICES` в режиме `socks` её не меняют; список `DEVICES` при этом ограничивает область временной блокировки обновления и перезапуска.

Режим `tun` создаёт устройство `tt0` и направляет через него трафик LAN и самого роутера, сохраняя прямой доступ к локальным сетям и заданным исключениям. Для выбора режима применяется `cattunnel set MODE tun`, после чего требуется перезапуск службы; непустой список «Настройки → Только эти устройства» ограничивает туннель выбранными устройствами.

При установленном nikki кнопка «Встроить в nikki» добавляет CatTunnel в его группы, оставляя существующий VLESS запасным выходом. Команда `cattunnel nikki off` возвращает сохранённый профиль байт в байт, если он не менялся после встраивания, а также восстанавливает mixin и прежний выбор групп. Если профиль был отредактирован отдельно, CatTunnel удаляет свои строки, сохраняя остальные изменения; резервная копия остаётся в каталоге профилей.

## Устройства через VPN

При непустом `DEVICES` туннель работает по требованию: первый пакет выбранного устройства запускает движок, а 600 секунд тишины по умолчанию останавливают его. Время задаётся параметром `IDLE_STOP`; значение 0 оставляет туннель постоянно поднятым, а пустой `DEVICES` направляет через него весь LAN.

Телефон с частным MAC целесообразно указывать по имени, которое он сообщает роутеру; допустим и префикс со звёздочкой, например `Phone*`. Сторож сверяет имена каждые 30 секунд, однако при отсутствии имени потребуется постоянный MAC в настройках Wi-Fi телефона.

Kill switch для выбранных устройств сохраняет блокирующий маршрут, пока туннель поднимается или недоступен. При `DNS tunnel` запросы этих устройств на порт 53 перенаправляются на DNS из подписки; DNS остальных устройств остаётся прежним.

## Российские сайты

Параметр `RU_DIRECT on` добавляет прямые исключения для российских доменов, встроенного списка сервисов и сетей geoip:ru, охватывающих около 26 тысяч сетей на момент проверки. Число меняется вместе с исходными списками; исключения применяет движок в режиме `tun`, включая трафик выбранных устройств; внешний прокси в режиме `socks` использует собственные правила.

Сети загружаются из списков runetfreedom и ipverse раз в 20 часов, а при сбое сохраняется прежний список. Состояние показывает `cattunnel ru status`, ручное обновление выполняет `cattunnel ru update`; отключение доступно в настройках или через `cattunnel set RU_DIRECT off` с перезапуском туннеля.

## Свои сайты и IP напрямую

Список «Настройки → Сайты и IP напрямую» задаёт дополнительные исключения для режима `tun`, в том числе при выборе отдельных устройств. Каждая строка содержит домен, шаблон поддоменов со звёздочкой, IP-адрес или сеть; из консоли список меняют команды `cattunnel direct add|del|set|list|clear`, а после изменения требуется перезапуск туннеля.

## Серверы

Подписка обновляется раз в 6 часов, причём при недоступности первого адреса используются сохранённые зеркала. Если выбранный сервер не отвечает 4 проверки подряд с интервалом 30 секунд, `FAILOVER on` переводит соединение на следующий сервер подписки; через 30 минут сторож пробует вернуться на выбранный.

При потере интернета самим роутером сторож ожидает восстановления сети, сохраняя текущий выбор сервера. Параметры `CHECK_EVERY`, `CHECK_FAILS` и `BACK_AFTER` изменяют интервалы проверок и возврата; эти значения относятся к сторожу CatTunnel, а резерв внутри группы mihomo настраивается отдельно.

Анти-DPI поддерживает способы 1, 2 и 3, собственную строку десинхронизации и режим «авто», который пробует способы 1-3 по 15 секунд и запоминает удачный для сервера. Настройки отдельного сервера переопределяют отпечаток TLS, анти-DPI, строку десинхронизации, маскировку размеров и QUIC. По умолчанию используются значения подписки; описание механизмов находится в разделе «Как устроено подключение».

## Безопасность

Kill switch включён по умолчанию и ограничивает трафик, направленный в CatTunnel, сохраняя явно заданные прямые исключения. При обновлении работающей службы через `install.sh` отдельная временная блокировка ограничивает транзит выбранных `DEVICES` до успешной проверки туннеля или истечения срока восстановления; остальные устройства сохраняют прямой доступ, а при пустом `DEVICES` блокируется весь LAN.

Остановка через `cattunnel stop`, init-скрипт или кнопку «Остановить» возвращает прямой интернет: правила устройств и kill switch снимаются, DNS восстанавливается, настройки и подписка сохраняются. Во время незавершённого обновления обычная остановка сохраняет защиту; команда `cattunnel stop --force` и кнопка «Остановить» снимают её явно, а `restart` и failover сохраняют блокировку.

Сертификаты проверяются по набору корневых центров роутера, из которого CatTunnel удаляет Russian Trusted Root/Sub CA и центры Минцифры. Эта фильтрация применяется к соединениям движка и загрузке подписки; начальная команда загрузки `install.sh` использует обычную проверку HTTPS в curl.

Подписка и ключи находятся в каталоге CatTunnel с доступом только для root. Обновление сохраняет `device.key`, а его удаление создаст для сервера новое устройство; прежний ключ пользователя остаётся запасным для совместимых старых серверов.

Установщик сверяет пакет по SHA-256 из своего текста, а `cattunnel upgrade` дополнительно проверяет подпись `install.sh.sig` ключом Ed25519 из пакета. Первая команда `curl ... && sh install.sh` сама по себе подпись не проверяет; для отдельной проверки на ПК команда приведена в README.

Метка `upgrade.pending` действует 15 минут, после чего временный барьер снимается при очередной проверке сторожа или вызове управляющей команды; живость lock проверяется по PID, времени и идентификатору загрузки. После завершения установщик ждёт подтверждения туннеля до 5 минут, а при выключенном автозапуске Entware или остановленной службе барьер установки не включается.

Наличие новой версии проверяется раз в сутки и показывается кнопкой «Обновить» на странице состояния. Команды `cattunnel upgrade check` и `cattunnel upgrade` проверяют и устанавливают обновление; при необходимости устанавливается openssl, отказ пакетного менеджера вызывает откат сохранённых файлов, а резервная копия требует дополнительного места в `/tmp`.

Веб-страница слушает домашний адрес роутера и требует пароль, от которого сохраняется хэш SHA-512 при наличии openssl, иначе MD5-crypt. Новый пароль задаётся через `cattunnel web password <новый>`, состояние автозапуска службы - через `cattunnel autostart on|off|status`; изменение автозапуска сохраняется при переустановке через установщик.

## Куда роутер ходит сам

На роутере сохраняются подписка, ключи и идентификатор устройства, настройки, списки прямых исключений и корневые сертификаты. Служебные файлы содержат состояние обновления и резервные копии интеграции с nikki; журнал движка ограничен 256 КБ, хранится в памяти и пропадает при перезагрузке.

Проверка туннеля обращается к `connectivitycheck.gstatic.com/generate_204`, а проверка сети роутера использует DNS провайдера с запросом `ya.ru` и резервные проверки адресов 77.88.8.8, 1.1.1.1 и 8.8.8.8. Списки российских сетей загружаются с `cdn.jsdelivr.net` и `raw.githubusercontent.com` из runetfreedom/geoip и ipverse/rir-ip; установщик и его подпись берутся с зеркал пакета, по умолчанию из релизов `github.com/Cattunnel/cattunnel-router`.

При импорте и обновлении подписки её сервер получает открытый ключ и случайный идентификатор устройства, версию пакета и сведения о платформе; проверка релиза загружает установщик и подпись, аналитика не используется.

## Техническая информация

Сборка движка закреплена на ревизии `82963908` TrustTunnelClient: то же ядро, что в Android 1.5.9, с исправлением Ed25519 для MIPS. На aarch64/armv7/x86_64 используется BoringSSL `boring-2026-05-08` с TLS-ключом авторизации и ML-DSA; mips/mipsel пока используют OpenSSL 4.0.2 без поддержки TLS-ключа авторизации `client_random_auth_key` (0x0F).

Скрипт `engine/build_router.sh` задаёт статическую musl-сборку; готовность конкретных бинарников проверяется по отчёту сборки. Для установки требуются Linux от 3.2 и память от 64 МБ, для `tun` также нужен `/dev/net/tun`.

Установщик выбирает aarch64, armv7, mipsel или x86_64, а сборщик дополнительно поддерживает mips big-endian, который автоматический установщик пока отвергает. Проверенный Keenetic - SmartBox Giga KN-1913 на MT7621 (mipsel); для OpenWrt 23.05/24.10 и Entware используются `.ipk`, для OpenWrt 25 - `.apk`.

Настройки находятся в `/etc/cattunnel/cattunnel.conf`, на Entware - в `/opt/etc/cattunnel/cattunnel.conf`. Команда `cattunnel settings` показывает значения, а `set` принимает несколько пар, например `cattunnel set MODE tun KILLSWITCH on`; параметры движка применяются после перезапуска службы.

- Состояние и проверка: `cattunnel status`, `cattunnel test`, `cattunnel devices status`, `cattunnel ru status`.
- Серверы и настройки: `cattunnel list`, `cattunnel use <ключ>`, `cattunnel settings`, `cattunnel set <имя> <значение>`.
- Диагностика: `cattunnel log 100`, `cattunnel report`, `cattunnel doctor`.
- Обновление и запуск: `cattunnel upgrade check`, `cattunnel upgrade`, `cattunnel autostart on|off|status`.

## Если что-то не работает

Проверку соединения выполняет кнопка «Проверить интернет через туннель» на вкладке «Состояние» или `cattunnel test`. Журнал находится в разделе «Диагностика», а `cattunnel doctor` показывает «Соседей по роутеру»: другие VPN, прокси, DNS-службы, pbr/mwan3, память и swap. Команда `cattunnel doctor --apply` применяет предложенную схему интеграции; с версии 1.5.5 монитор сети движка учитывает маршруты в отдельных таблицах mwan3/pbr.

Для устройства, не попадающего в туннель, `cattunnel devices status` показывает найденные имена и установленные правила. При недоступности российских сайтов проверяются `RU_DIRECT` и `cattunnel ru status`; на Keenetic со старой версией пакета также следует учитывать исправления обхода туннеля ускорителем соединений.

Для обращения к администратору предназначен обезличенный `cattunnel report`, который не экспортирует подписку и ключи. Дополнительный журнал выводит `cattunnel log 100`; пароли из конфигурации движка в него не добавляются.
